# ADR-093：消费端问题在项目本地归因和上报

## 背景

日常开发的任务即使成功，也可能经绕行暴露 Nova 能力缺口。漏触发协作入口时，故障证据可能出现在入口之外。项目的真实代码、包版本、工具执行与环境证据在消费端才能相互核对。

## 决策

- 加入上报的项目由独立的本地生命周期入口观察任务执行。被观察的能力与观察入口各有触发条件，能够记录任务预期入口、真实调用和结束结果。
- 项目自行启用的任务观察由宿主执行授权审查。框架准备本机可发现的配置并说明采集用途及上报范围，宿主记录成员的选择。框架升级沿用完整的原有反馈定义和执行内容。原有反馈钩子未授权或停用时暂停当前任务，等待成员开启反馈或明确选择暂缓。暂缓在当前框架版本的当日有效，跨天或升级后重新核对，直到反馈已授权并开启。配置须符合工程的 Git 忽略规则，具体入口与任务恢复条件见项目组说明。
- 基础环境由 Editor 按工作区每小时检查。首次采集或环境变化时上报，环境相同则跳过。检查时间与环境签名保存在工作区账本。版本和钩子配置数量由同一份快照保留，展示使用采集时间。Action 按 Execute 终态保存版本、时间和结果，以共享操作身份合并 Codex 与 Editor 的观察。
- 钩子运行证据由本机实际处理成功的事件产生。工作区首次执行时独立上报，后续活动限频。服务端按实际发生时间汇总各工作区的最近运行，启动 Editor 和环境快照各由自身规则触发。
- Unity MCP 桥接状态取自当前 Editor 的 Provider。Codex 工具调用取自成员独立授权的工具回执钩子。上报只携带稳定工具标识和结果，Nova Action 继续按既有执行回执计数。
- 运行证据保留实际来源。Editor Play 对已接入模块的调用先在内存累计，按批入队，表注册单独记录。早期仅记录场次的使用证据保留原义。Pipify 记录整个 Batch 的终态及可确认的失败步骤，人工导出按入口的实际结果记录。工程实施上报服务于配置、验证、构建和使用汇总。协作记录收录能直接核对的入口、检查、操作回执和终态，覆盖 Editor 启动、Framework 升级、队列恢复和正式发布流程。
- 当前项目的本地 Agent 核对归因，区分已证实的缺口与待取证线索。自动确认入口遗漏需有同一轮的成功执行回执和实际入口记录佐证。发送固定字段、脱敏证据和稳定上报标识，服务按原标识返回接收回执。
- 执行任务的 Agent 在确认可归因的框架问题时，按当前反馈授权提交证据。任务收尾以可追踪的待发记录或服务回执核对反馈结果。项目自己的问题文档由项目维护。
- 本地观察入口用当前任务的报告记录复核收尾。结论中出现明确的归因线索且缺少本轮报告时，恢复任务复核一次。归因和授权仍以本机证据核对结果为准。
- 已确认归属 Nova 包的编译与导入错误是独立的问题证据，由消费端 Editor 及时入队。编译回调提供直接位置，属于当前工程的 Editor 日志可补齐观察入口就绪前的错误。保留包及其版本、包内位置和错误类型，同一工作区在相同版本下复用上报标识。
- 工程实施状态沿用各入口已有证据。工作区和版本共同限定证据归属。SDK 的自动反馈范围为安装、配置启用和 Android／iOS 构建。
- Agent 的本地运行记录写入已有 Git 忽略的项目 Library。报告按维护端实际使用的字段上报。在服务确认原编号之前，队列按原编号和正文补发。确认后在同一事务里保留短期去重回执并清除本地正文，服务端负责保存已接收的历史。
- 服务每天先备份再归档。使用和协作明细可在线查询近 30 天，压缩明细保留至 365 天。归档与在线明细移除使用同一事务，保留模块历史、最近成功证据及 Action 去重身份。问题、环境快照和构建结果继续保留以供追溯。
- 操作发现、规则和当次证据见 [Nova 问题自动反馈](../../../Docs/Onboarding/NOVA_ISSUES.md)。观察已执行操作复用 [[ADR-081-project-action-controlled-execution-layer|ADR-081]] 的稳定身份及回执。

## 后果

维护者能识别重复问题、适用版本和已取得的证据。工作站需要真实接入与任务观察能力，覆盖以运行产出的证据为准。Library 清理后重新取得环境和本地观察，服务端仍提供近 30 天的使用和协作明细，以及历史问题与模块证据。

## 验证依据

核对宿主能够发现待审查的项目配置，并保持成员授权决定。以一条绕行完成的实际请求验证路由遗漏判定，用正确路径和等待用户决定的任务校验归因。用断线补传、错号回执、同号重试及旧队列迁移验证待发正文保留、已确认正文清除和历史去重。运行入口与验收方式随 [本地 Agent 文档](../../../Docs/Onboarding/NOVA_ISSUES.md) 更新。

以消费工程原生日志和逐程序集编译消息核对包内位置、错误归属及版本。重复导入错误应进入同一个上报编号，业务源码和其他工程的日志应排除。

用过期明细、迟到补传和同一次 Action 的双份回执验证归档边界、去重与历史统计。备份失败时验证原始明细仍可读取。
