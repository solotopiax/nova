# PAT-05：L0/L1/L2 三级文档体系 + S 级标准

## 适用场景

- 代码规模已大到不能只靠源码导航
- 需要给实现、Review 和日常调用提供稳定入口
- 希望 `Docs` 始终保持“当前事实层”而不是散笔记集合

## 核心结构

| 层级 | 文件 | 作用 |
|---|---|---|
| `L0` | `ARCHITECTURE.md` | 框架总览 |
| `L1` | `Runtime.md` / `Editor.md` | Runtime / Editor 导航 |
| `L2` | 各类 `<ClassName>.md` | 类、接口、窗口、组件事实说明 |
| 入口 | `INDEX.md` | 全局入口与任务导航 |

## 核心原则

- 上层不展开下层细节。
- 下层不重复上层背景。
- `Docs` 只写当前事实，不写历史决策。
- 新建、删除、重命名类时，`INDEX` 与父级导航一起同步。

## 当前事实只维护一份

| 内容 | 维护位置 |
|---|---|
| 签名、类型、默认声明和实际行为 | 源码；参数含义、空值、失败和局部所有权紧邻方法写入中文 XML |
| 跨方法流程、配置来源、生命周期和使用差异 | 既有类或模块 `Docs` |
| 任务授权、写入范围、锁、恢复与最低证据 | 所属 Skill/Action 执行契约 |
| 符号身份、位置、指纹和文档引用 | 从当前源码自动生成的定位索引 |
| 长期设计原因、术语和可复用边界 | `Minds` |

自动索引提供导航，不复制人工语义、不记录全库审查完成率。索引可重建与删除；查询按当前问题读取命中来源，全库一致性检查由维护者显式执行。两者不能变成每次查询都读取全部文档或重审全部函数。

## L2 文档要求

复杂类型保留较完整结构，至少覆盖：

- 文件拆分
- 公开 API
- 关键字段或关键状态
- 使用示例
- 关联文档

小类型允许极简，不强行凑满大模板。

公开 API 与高风险行为应说明输入、输出、失败及必要生命周期；普通 helper 的局部含义保留在邻近 XML，不为每个函数强制建立重复的多维知识文件。文档记录当前规则，验收结果在当次任务中报告。

## 反模式

- 每篇文档都重复同一套背景
- 小枚举和小接口硬套重模板
- 改代码不改文档
- 删代码却把文档留在 `Docs` 里当历史资料
- 把索引、XML、Docs 都写成同一份方法语义，更新时必须人工同步多份副本
- 用生成成功、链接存在或指纹匹配冒充语义已审或运行已通过

## 来源与影响面

- [自然语言开发入口](../../../Docs/Onboarding/NATURAL_LANGUAGE_DEVELOPMENT.md)：当前事实落点、按需查询与显式维护检查。
- 本模式适用于 Framework 及随包文档；消费项目查询无需依赖开发仓 `Minds`。
