# 任务信息模板

用于[研发方法论](../../../../Docs/Onboarding/AI_DEVELOPMENT_WORKFLOW.md)中信息不足的分支。优先读取项目和本轮已有内容补齐，简短说明即可；不要求用户填写完整表格，不默认新建持久化计划、记忆或评审文件。

## 通用任务约定

```text
本轮结果：用户能看到什么变化。
范围与保留条件：改哪里，哪些既有行为必须保留。
当前依据：准确入口、相关实现/配置、可复用能力。
验收：用什么输入与操作，观察什么结果。
关键未知：哪些未知会改变方案；谁能决定或怎样验证。
```

小改可以只用“目标＋保留条件＋局部检查”一句话，不为形式补齐所有字段。

## 探索或玩法实验

```text
要验证的假设：本轮只解决的关键不确定性。
实验：最少需要实现或展示什么，从什么入口体验。
观察：怎样判断理解、体验或技术可行性；少量主观反馈如实标注。
投入与结束条件：本轮允许的时间/范围或最小交付边界。
结果后的选择：继续、调整或放弃；记录依据和仍未知的部分。
```

例如尚未确定是否采用拖拽合成，先验证一次拖入、反馈和撤销是否易懂。不能把一次试玩当作整体玩法已验证；实现仍走当前项目的 UI、输入与业务边界。

## 功能开发

```text
结果：从现有入口完成的一项用户行为。
规则：已确认的数据、单位、限制、失败和重复行为。
依赖：本次需要的源、配置、正式导出、资产与业务调用。
本轮小步：能独立使用和验收的范围。
验收：正常输入，及本次相关的失败/退出条件。
```

例如设置页音量调整：先查真实音量状态、保存源与声音入口；验收页面打开、拖动即时生效、关闭后状态保留，以及本次要求的重启恢复。数值、字段与保存接口从当前实现确认，不用示例推断。

## 缺陷修复

```text
现象与预期：客观差异。
复现条件：版本、平台、入口、操作和必要数据。
已有证据：最早错误、实际调用链、可排除与尚不能排除的原因。
本轮假设与修改：为何它解释现象，影响哪些相关行为。
验证：原故障是否消失，必要的邻近行为是否仍成立。
```

根因未知时先定位，不先批量改写。验证能复现错误并区分修复前后，才比只匹配实现文字更有价值。

## UI 与交互

```text
目标：哪个真实页面或控件，应出现什么变化。
当前状态与参照：已有 Prefab/布局、设计图或可核实的样式。
适配：产品方向、目标比例与安全区、缩放和避让的已有拥有者。
交互：输入、禁用/空态/失败态及本次相关的开关或退出行为。
验收：对应视口的显示与真实操作；需要目标设备时明确边界。
```

图片、预览和设计稿在视觉任务中可以是必要输入，按需查看；不把“大文件”作为拒绝观察实际界面的理由。

## 重构或契约变更

```text
问题：当前结构造成的具体维护、缺陷或兼容问题。
目标：可观察的改善，保留哪些外部行为。
影响：接口/调用方、序列化/旧数据、配置/导出、初始化与退出。
方案：优先复用的既有结构，必要的迁移与恢复路径。
验收：行为与兼容要求分别需要什么证据，哪些外部消费者尚不能验证。
```

## 交接或恢复

```text
目标与当前边界：本轮有效的需求和授权范围。
当前事实：准确工程、版本、相关入口及事实源位置。
已做与已验：分开说明，注明证据覆盖层级。
待解决：未确认的规则、失败原因或外部条件。
进行中：运行任务、未完成事务与必要恢复位置；不包含密钥值。
下一步：恢复后先核什么，再做哪个独立动作。
```

交接保留当前可恢复状态，稳定决策再合入原有项目说明；不默认把对话历史写成长期知识。
