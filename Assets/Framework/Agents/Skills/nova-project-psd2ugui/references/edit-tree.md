# 编辑树、来源与配置

仅在查询或编辑 PSD2UGUI 树、同步设计源、设置节点类型/名称/引用时读取本页。先用 `inspect` 查当前配置与来源；写入只通过 `run` 当前开放的固定操作。

## 冻结对象

设计源、编辑树、生成界面分别记录真实身份。读取当前生效配置及它的来源，不能从同名配置中任选第一份，也不写包内模板。建立树前确认已有树和输出记录；存在用户编辑时不得把重建当成无损刷新。

更新设计源后使用受控同步入口，并核对节点来源 ID、保留节点、新增节点和失效引用。同步以 ID 保留已有 AI 树；新来源可能追加为根部 `Null`、不导出节点，不能因此宣称新控件已生成。删除或找不到来源的节点须单独核对，不直接删除设计源或生成记录。

## 节点含义与修改

- 写入的 `nodes[].id` 必须是本次 inspect 返回的 `persistentId` 字符串，不按节点名称模糊定位。节点名称、节点类型、层级与 PSD 来源分别核对。改编辑树名称不会改 PSD 图层名，也不会自动重新分配来源；变更前后都读回来源身份。
- `img` 表示独立 Image；`bg` 表示所属控件的子部件，孤立 `bg` 可能不生成。不能用批量改为 `bg` 修复所有图片。
- 文本图层可自动识别，无须为了生成文本统一追加后缀。“优先 TMP”可将默认 Text 改为 TMP，实际字体必须有项目可用的 Unity 资源，不能只填写操作系统字体名。
- `markToExport` 仅控制批量导图选择，不控制界面生成或显隐。用户说“隐藏”“不生成”时先查真实支持方式，不借这个字段实现。
- 节点引用按钮跳到来源节点不证明绑定错误；最终生成对象的 `Source Image` 与引用资源才是图片绑定证据。

## 共享图片引用

`ref` / `refp` 是图层名称中的前缀，前缀与路径之间使用空格；路径相对于当前配置的共享目录，推荐写完整扩展名。先读实际共享目录与目标资源，不把相对路径当作工程根目录路径。

普通树与 AI 树的引用来源不同。AI 节点初始共享引用来自兼容 PSD 来源；只改 AI 节点名称不会改变引用。本版 `patch-nodes` 可用 `referenceKind` 与 `referenceKey` 明确修改引用：普通节点会更新引用名称，AI 节点会更新专门的引用信息。它不改变节点的 PSD 来源；后续同步或重新应用 AI 仍须检查来源规则是否覆盖人工引用。需要长期跟随设计源时优先在 PSD 声明后同步。

设置引用须同时提供 `referenceKind=ref/refp` 与目录内相对路径 `referenceKey`；不能只给 key。清除引用使用 `referenceKind=""`，不同时提供非空 key。普通节点不能在同一补丁中既指定独立名称又指定新引用，避免相互覆盖。拓扑新增或来源不兼容时需重新识别，不能靠改名或手补 GUID 伪造映射。

## 证据

保存后读回本次精确节点、类型、名称、层级、来源与引用，核对非目标节点未受影响。仅查询配置不保存；配置编辑必须由当前 Action 明确列出的配置操作承载，不将任意配置路径、私有字段或方法名塞入请求。

`configure` 使用已开放的字段；`forceUseTMP` / `nineSliceBorderTolerance` 只有相应 `hasForceUseTMP` / `hasNineSliceBorderTolerance` 标志时才表示修改。`defaultTextType`、`defaultImageType`、`aiMode` 从当前精确枚举取值；`copyPromptTemplates` 仅复制缺失模板，不覆盖已有文件。共享目录、输出目录与配置资产分别冻结，不把一次节点编辑扩大成配置重写。
