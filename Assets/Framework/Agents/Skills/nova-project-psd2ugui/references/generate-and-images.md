# 生成界面、导出图片与页面接入

仅在生成/更新 uGUI、导出图层图片、处理九宫格或接入 Nova 页面时读取本页。当前操作是否可执行由 live `describe`、`inspect` 和 Plan 决定。

## 输出与覆盖

生成前读取当前编辑资产的输出记录，并确认文件是否存在。已有输出文件仍在时，插件按文档中的 `uiFormGuid` 继续更新它；即使在 Unity 中移动了文件，也会跟随实际位置，更改导出目录不是另存为。旧文件确实已不存在时，完整生成会使用当前有效的 UIForm 导出目录，成功后自动记录新关联，无需手动清空 GUID。局部更新仍要求原输出存在；新目录有同名未登记资源时会避让，不直接覆盖。

用户需要复制或另存时，先查专门入口与身份规则；没有受控入口就明确该缺口，不清空 GUID、删 `.meta` 或删生成记录强迫重新创建。

“生成界面”与“导出图片”分别计划。批量导图选择依 `markToExport`，它不决定生成控件或显隐；导图前确认输出目录、覆盖范围与确切选中节点。保留真实来源，不能用整页截图代替要求保留可编辑层级的页面。

## 图片、文字与九宫格

- 根据设计含义核对 `img` 独立图片和 `bg` 控件子部件；验最终对象的 `Source Image`，不只看节点名或定位按钮。
- 文字识别、Text/TMP 选择与实际字体资源分别验收。检查生成文本、字体引用、缺字和布局，不因模板上有文本组件就认定字体可用。
- 九宫格需要生成 Image 的 `Type` 与 Sprite 的 `Border` 同时正确。容差用于识别判断，不是边框宽度；只改容差或只改 Image 类型不能证明九宫格完成。
- AI 生成按控件模板决定九宫格，不读取 PSD 图层名中的 `.sliced` 等后缀来替代模板设置。只有当前 Action 提供相应受控操作才修改模板、类型或 Border；否则保留具体未覆盖项。

## 进入 Nova 业务页面

先核实目标是纯 uGUI 产物还是需要完整业务页面。后者继续已有 `nova-project-ui-create-view` 或 `nova-project-update-ui-view`，完成资源地址、表源/正式导出、绑定及实际入口。

`UIView` 是抽象基类，须使用项目具体业务子类；生成模板预挂业务脚本并不保证保留。首次生成会清理新增对象上的非 UGUI/TMP 脚本，已有输出的脚本保留也须在本次生成后重新核对。不要把首次生成前的绑定当作最终绑定证据。

业务子类的 `OnInit` 按 Nova 当前契约调用 `base`，并确保所需 Canvas / GraphicRaycaster；实例根 CanvasScaler 由 `UIComponent` 控制。具体顺序、字段与适配按当前 UI 模块文档和同类项目实现核实，不在插件模板中加入竞争的缩放或安全区实现。

## 验证与清理

用回执只读核对准确输出路径、实际资源及引用；针对本次修改检查图片、文本、九宫格和目标比例。独立预制体还要检查文字、图片等子节点与父控件的相对位置，根节点归零不应把子节点留在整张 PSD 的绝对位置。新增脚本先编译，要求业务打开/交互时从真实页面入口验收。

保留 PSD/PSB、编辑 `.asset` 及 `.meta`、正式输出和生成记录。清理仅针对当前 Action 支持且已计划的精确范围；未开放清理时不手工删除这些持久身份材料。验证临时资产和本轮辅助窗口按共同入口收尾。

遇到示例的 `Authoring~` 时，先读取该示例 README 并检查插件是否安装：其中可能是缺插件时自动收起的编辑数据，不是垃圾或旧备份。保留文件和 `.meta`，不要强行复制出第二套同 GUID 资产。该保护不等于任意项目资源都能安全卸载；移除插件前保存并关闭编辑树，并按包管理流程核对实际消费者。生成的 uGUI 与插件编辑树分别检查依赖，不能因为产物可用就删除来源记录。示例目录和公开分发边界见 [Docs/Onboarding/PROJECT_STRUCTURE.md](../../../../Docs/Onboarding/PROJECT_STRUCTURE.md) 的 Sample 小节。

消费工程导入 MainDemo 后，核对编辑树源路径、`Psd2UIFormConfig` 的复用目录和 `.ui.asset` 的输出记录都已指向本次实际 Sample 目录；不能只检查 Prefab 的 PSD 对象引用。缺插件时路径清单仍需处理 `Authoring~` 中的数据，恢复后保持 GUID 不变。工程级图片、UIForm 与 AI Prompt 目录另由当前设置决定，保留用户自定义路径；可写产物始终留在 [Assets/（项目位置）](../../../../Docs/Onboarding/PROJECT_STRUCTURE.md)，不把 Sample 路径统一改成 [Packages/（包定位）](../../../../Docs/START_HERE.md#先确定框架位置与文档入口)。多个配置共存时以本次源/编辑树邻近配置或明确的 `configAssetPath` 为准，空查询、当前选择和正在编辑的目标不能混为一谈。
