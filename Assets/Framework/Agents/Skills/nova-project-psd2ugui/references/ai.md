# AI 识别与应用

仅在用户要求 AI 识别、重新识别或应用已缓存结果时读取本页。先通过当前 Action 读取目标编辑资产、来源、配置、可用服务与 CLI 状态；不把包安装成功或可执行文件存在当作已登录、可成功调用。

## 执行前

冻结本次设计源、编辑树、AI 服务、输入输出和覆盖范围，并核对调用会使用的账号/凭据及外部处理是否属于当前授权。用户只要求本地生成或看配置时不自动运行 AI。缺真实许可证或 AI CLI 登录时精准报告缺项，不跳过许可检查、不替换凭据、不自行切换提供方或开启无限重试。

读取现有 AI 结果与人工编辑状态。新识别在准备成功后会清除上一轮结果，不能承诺失败后旧结果仍然可应用；新的 Plan 应展示该边界。现有人工修改必须纳入覆盖判断，不能把重新识别当作只读诊断。

## 运行与应用是不同目标

自然语言受控入口的 `run-ai` 只执行识别，不弹确认框，也不自动应用。等待本次 Receipt 的只读 Verify 明确成功后，用其中的准确 `jobId` 新建一次 `apply-ai` 计划并执行；不得由 Verify 轮询触发应用。应用后检查树和来源，再按用户目标执行 `generate`。这组编排由 Agent 完成，项目组不需要记住两个调用。

插件窗口的 AI 按钮仍会在成功时自动应用；不要把它与上述 Action 行为混淆。若用户刚从窗口完成识别，先检查已应用状态，不无条件重放 apply。

手动 apply 只重新应用缓存结果，可能覆盖人工改名、层级和类型。用户要求保留人工调整时，不以 apply“刷新”画面；需要应用旧缓存时冻结准确缓存及受影响树，并核验保存结果。

AI 树允许人工调整名称、类型、层级，但这不会自动重分配 PSD 来源。不能只改 AI 节点名就改变 `ref` / `refp`；本版可通过明确引用字段修改，规则与后续同步影响见[编辑树与来源](edit-tree.md)。新增拓扑需要重新识别，不把简单 sync 当作完整 AI 识别。

当前 `patch-nodes` 提供名称、类型、引用与导图开关，不接受重排层级参数。窗口可编辑的层级能力不能冒称已有 Action 可调度；目标需要该能力而当前工具未开放时，明确这一个缺口，继续完成不依赖它的步骤。

## 验收

分别报告本次 CLI/服务结果、生成结果文件、实际应用状态、保存后的树与来源，以及生成界面的视觉证据。命令退出或有缓存文件不等于本次应用成功。AI 结果与真实源不匹配、人工编辑被覆盖、来源缺失或任务中断时保留准确 `partial` / `blocked`，按回执只读核验，不自动重发 AI 请求或重放 apply。
