# 验证与构建

验证只覆盖本次操作影响的真实链路：源码与配置、正式导出、编译、Play、Player、设备和外部服务分别说明。检查通过只证明其覆盖范围，不继承历史成功记录。

## 前置问题的原因与防复发

这些问题的共同原因是：未在开始依赖工作前核实前置条件，又把局部操作成功扩大为整体就绪。Nova 协作体系须把“原因 → 前置检查 → 执行入口 → 实际证据”接通，不能仅新增一句提醒。

| 问题 | 原因与判断边界 | 防复发要求及验收 |
| --- | --- | --- |
| 弹窗阻塞、工具超时后反复重启 | 缺少当前窗口与进度观察，混淆模态等待、编译错误、正常忙碌和进程故障。重启可能重新遇到同一提示；不能据此推断所有历史重启都由弹窗造成。 | 按下节在首次超时立即查窗口，及时处理已授权提示，验证交互与只读查询恢复；只有新的故障证据才支持重启。 |
| 操作结束后辅助窗口遗留或再次打开 | 只核对工具返回、文件或前台窗口，遗漏后台窗口、停靠标签页及后续流程再次开窗的情况。 | 按 NA-014 的辅助窗口收尾要求，在对应操作结束后关闭，并在最后一次可能开窗的操作或异步回调完成后再次核查；必须取得窗口已关闭、目标主窗口可见的当前证据。 |
| UI 做完后才补适配，重复缩放或安全区错误 | 未先确定方向、参考尺寸、支持比例和布局拥有者，或混淆屏幕像素与画布坐标；只看单屏效果就扩大结论。 | 按 [屏幕适配](../Runtime/Modules/UI/UIComponent.md#屏幕适配与安全区) 先定方案并复用根画布，明确唯一安全区拥有者；实际入口覆盖约定边界比例、刘海区域和重开/方向变化。 |
| 启动资源、配置和预加载准备遗漏 | 把 Prefab 字段有值当成实物已导入，把 Sample 示例当成已完成的项目接线，忽略字体、贴图、文本、正式导出与加载顺序。 | 按 [开工准备](PROJECT_STRUCTURE.md#新项目开工准备) 和 [固定启动资源](RESOURCE_WORKFLOW.md#新项目默认固定启动资源) 逐项准备当前阶段依赖，保存读回并验证最小启动；每个实际模块核对结果，进度完成不代替可用。 |
| HybridCLR 未安装却报告成功 | 把 UPM 包解析或禁用 HybridCLR 后的普通 IL2CPP APK 成功，当成本地工具链安装与热更链成功，未在交付中单列缺项。 | 按 [安装与验收](../Editor/EditorUtil/EditorUtil.Environment/EditorUtil.Environment.md#hybridclr-安装与验收) 分层核对并明确未完成项；禁止关闭开关或改版本标记绕过，普通 APK 只证明其实际构建与运行范围。 |

复盘发现遗漏后，沿同一依赖链检查上游来源和下游消费者，修正对应入口、合同和验收要求，并补充可复用原因。每条原因区分直接证据与推断；没有证据不能补造根因，新增文字也不表示历史缺项已修复或现有项目已重新验收。长期沉淀只保存稳定原因与防线，当次日志、执行进度和结果不另存为历史验收档案。

## Unity 窗口处理与恢复顺序

本节是 NA-014 的执行步骤，适用于 Unity、Package Manager、第三方依赖工具、Nova 安装/更新提示及宿主系统窗口。窗口标题只用于识别，按钮选择取决于当前真实内容与任务授权。

1. **先认准工程**：核对工程路径、Unity 版本、进程及窗口归属。首次打开或重连、包安装/Resolve、编译重载、平台切换、Play 和构建期间主动检查；长调用优先使用可返回任务状态的方式，等待时通常每 10～30 秒查看一次进度或窗口，不只反复 ping，也不让一次长等待遮住弹窗。首次工具超时、进度停滞或已看到弹窗时，下一步立即查看窗口，不能再耗费数轮超时才检查。
2. **及时处理当前窗口**：优先用能读取真实窗口的现有工具；MCP 主线程不响应时，改用当前宿主可用的原生 UI/辅助功能或截图工具检查，不能依赖同一阻塞通道来证明“没有弹窗”。点击前读取新鲜窗口和按钮状态，一次处理一个窗口，点击后重新检查；不盲点旧坐标、连续发送回车或把所有确认都选成同一按钮。可逆的关闭、确认已读沿用已有同范围授权直接执行。
3. **按内容选择动作**：参考下表。关闭提示不等于修复底层错误，必须保留需要继续定位的问题；只读诊断仅观察并报告，既有开发任务可在已授权范围先处理窗口，再进入只读诊断。缺少可用 UI 通道或确需用户选择时，立即说明具体阻塞和所需动作，同时继续独立工作，不以重启代替。
4. **验证恢复再推进**：确认阻塞窗口消失、目标 Editor 可交互、工具只读查询恢复，再检查 Console/包状态。正常导入或编译有进度则继续等待；编译错误按最早直接错误修复，不能归为卡死。Action 结果未知时先用原回执/recovery_token Verify，不能因窗口已关就重放 Execute。
5. **重启是有依据的恢复步骤**：仅在必需重启提示、进程已退出/崩溃，或排除模态窗口与正常忙碌后仍有明确无进展证据时考虑。记录原因、未保存内容与在途操作，安全保存或恢复后按同一路径和版本重开，并马上复查弹窗与连接。恢复失败先分析新增证据；禁止以同一超时循环重启、杀所有 Unity 进程或默认删除 Library。没有证据时，不能把历史重启全部归因于弹窗。
6. **操作后关闭，交付前复查**：按 [NA-014](DEVELOPMENT_CONSTRAINTS.md#na-014授权范围实时合同和恢复回执约束实际执行) 确定本轮辅助窗口的关闭范围，逐项检查 Project Settings、Package Manager、TMP Importer、Nova 配置/检查窗口等，包括非前台窗口和停靠标签页。最后一次可能开窗的操作或异步回调完成后再检查，重新弹出就再次关闭，不能以中途关过一次代替最终核查。关闭后确认目标 Scene/Game 或用户指定的主窗口可见、可操作；无法安全关闭或仍有可能再次开窗的流程时，明确保留项及原因，不宣称窗口清场完成。

| 当前窗口 | 处理与边界 |
| --- | --- |
| `Packages with Errors` | 及时关闭阻塞，仍需核对包解析与 Console 的具体错误；可按任务打开 Package Manager 定位，或先 `Dismiss` 再查。不得默认 `Dismiss Forever` 永久隐藏，也不能把弃用/签名 Warning 一概当编译失败或凭弹窗自动改包版本、registry。 |
| `Enable Android Auto-resolution?` | 核对当前 EDM4U 设置、已冻结的解析范围和网络/生成副作用，按 `nova-project-resolve-android-dependencies` 决定启用或保留手动解析。不能为消除弹窗随手切换 Enable/Disable；手动模式仍须在构建前完成必要解析。 |
| Nova 安装、工具链、重要更新或已读提示 | 读清内容后，在当前安装/更新任务已授权范围及时确认或关闭，并按工具链状态验证后续步骤；涉及新的安装、下载、协议或权限时按相应合同判断，已有同范围授权无需重复询问。 |
| 保存、安全模式、升级、授权或权限请求 | 保存按本轮目标及所有权处理；安全模式先定位编译错误。涉及未知用户改动、不可逆升级或范围外副作用时保留现场并请求必要决策，不盲目接受。 |
| Project Settings / Package Manager / TMP Importer 等普通辅助窗口 | 普通窗口未必阻塞 Editor；按 NA-014 识别本轮归属，完成必要读取/操作后必须关闭并复查，回到目标主窗口。不能仅因它在前台就判卡死，也不能借关闭窗口擅自改设置。 |

这些是 Agent 执行要求，并非后台自动点击器；未取得当前窗口证据时保持对应缺口，不宣称已清除弹窗。

## 构建前只读检查

需要确认当前项目能否进入构建准备时，使用 `nova-project-preflight-build`。它调用 `nova.project.build.inspect-readiness`，底层探针归属 `EditorUtil.Build`，核对：

- 请求平台与活动平台、对应 Build Support。
- 启用的 Build Settings 场景存在且可解析。
- 持久化 ConfigMaster 绑定、Platform/Channel/DevelopMode 和导出的 Runtime 坐标。
- 场景 Asset/App 的渠道快照与 Runtime 一致。
- YooAsset Settings、Collector、Package，以及启用 HybridCLR 时的安装与 link.xml 配置。

Action 的执行成功表示检查完成；还需读取 `ready`、错误数和逐条规则。`ready=true` 只证明当前前置条件，没有执行 Bundle、Generate 或 Player，也不证明设备运行正常。检查不写配置、不导出、不切平台、不修复。

新项目完整开工还须满足 [准备清单](PROJECT_STRUCTURE.md#新项目开工准备)。HybridCLR 在禁用分支未被探针阻断，不表示本地已安装；安装、启用、生成与运行按 [独立验收层级](../Editor/EditorUtil/EditorUtil.Environment/EditorUtil.Environment.md#hybridclr-安装与验收) 报告。普通 IL2CPP APK 的构建或启动成功，不能代替 HybridCLR 环境或热更验收。

## 场景与资源检查

Agent 仍需按实际运行入口核对完整 canonical `Nova.prefab`、唯一 Nova 拓扑、Content 加载/卸载所有者及必需引用。仓库中未参与本次运行的替代入口、Sample 和插件 Demo 不属于当前运行闭包；插件 Resources、BuiltIn Resources 或不同于 Sample 的目录不等于错误。

Nova 已移除 Project Guard 的窗口、规则 Profiles 和自动 Play 检查。上述使用规范由任务中的检查与真实运行验证落实，不再依赖旧报告或自动拦截承诺。

## 合法构建入口

Unity Build Profiles、`BuildPipeline.BuildPlayer` 与 `EditorUtil.Build` 都可以构建 Player。Pipify 的 `build.package` 可批量串联导出、Bundle 和 Player；它不自动运行完整只读预检，组合任务应在构建前显式调用对应 Skill。

构建参数见 [EditorUtil.Build](../Editor/EditorUtil/EditorUtil.Build/EditorUtil.Build.md)，流水线见 [EditorUtil.Pipify](../Editor/EditorUtil/EditorUtil.Pipify/EditorUtil.Pipify.md)。

## Agent 验证顺序

1. 冻结本次目标、入口、场景闭包、平台与最小写入集。
2. 对照任务检查实际配置与结构；构建任务按需执行只读预检。
3. 只修已授权的问题，建议与未知项单独说明。
4. 按本次最低证据执行编译、Play 或构建；只有任务需要时才进入设备或外部服务验证。
5. 在对话报告本轮结果并清理临时对象、日志和测试态；不向包内提交历史验收记录。尚在使用的事务备份按工具恢复生命周期处理。
